# T04 — Document Intake and Preparation

Status: specification ready; execution after T02/T03. Date: 2026-09-27. Implementation and environment are not created in the planning session.

## Goal and Basis

Convert a single file, Telegram album, or Several pages set into one ordered temporary document without losing pages or mixing owners.

Basis: [PRODUCT_SPEC](../docs/requirements/PRODUCT_SPEC.md), REQ-002/003/011/012/015/019/020/025/026; [USER_FLOWS](../docs/requirements/USER_FLOWS.md); [DATA_MODEL](../docs/architecture/DATA_MODEL.md).

## Scope and Dependencies

- Depends on [T02](T02-application-foundation.md), [T03](T03-access-and-profiles.md), [CONTRACTS](../docs/architecture/CONTRACTS.md), and [OPERATIONS](../docs/operations/OPERATIONS.md).
- Authorized private-chat user only; one unfinished document per user. A file is not downloaded before login; a new separate document does not silently displace the active one.
- Standard Bot API, 20 MB per file. No custom lower limit or hidden first-pages-only limit.
- A single image/PDF starts automatically; a Several pages set is collected until Process; Process with no files reports that no document is present.
- Collection/clarification period: 15 minutes of inactivity, configurable. The exact short album completion window and definition of activity are specified in OPERATIONS.

## Implementation Result

1. A Submission is created with an owner, job ID/generation, and stable file/page IDs; page order is preserved within PDFs, and albums are sorted by message ID.
2. Temporary paths are generated by the application within the job directory; the original name, MIME, or extension is not treated as a trusted path/proof of format.
3. Download availability and actual format are checked. Images are decoded, PDFs are opened with a safe parser; contents are not executed and external links are not opened.
4. A corrupt/protected PDF, unsupported format, and download error receive an explicit English-language outcome. The document password is not guessed.
5. PDFs are rendered in a streaming/page-by-page manner within memory limits, without loading all rasters at once. Working image/page-batch limits are documented; the full document is not truncated to fit the model context.
6. Preprocessing does not overwrite the original. Orientation/scale and source association remain traceable within the temporary job.
7. Redelivery of a Telegram update does not duplicate a file. Messages from different users and media groups are not placed in the same set.
8. A late fragment of the same album before the result is finalized invalidates the previous pass: cancel/terminate the worker, complete the collection, and run a new pass without the old response. After a response has been sent, the result is marked incomplete and Several pages is offered; the fragment does not silently become a new document.

## Acceptance and Checks

- PNG, JPEG, single-page and multi-page PDFs, albums, and mixed image/PDF sets produce the expected order, page count, and source of every page.
- Process with no files, Cancel, repeated update, late album, a second document file while a job is active, and another user's callback are checked.
- False extension/MIME, incorrect path/name, corrupt PDF, password, download error, and Bot API limit are checked; the parser does not execute the document.
- A large multi-page input either processes all pages in batches or ends with an explicit error, without a successful incomplete result.
- 15 minutes of inactivity lead to expiry and cleanup; late files/buttons do not revive an expired job. The timeout configuration is checked.
- Preparation error, cancellation, and restart clean up originals/derived data; contents are absent from logs/backup. A running parser/worker does not read a file that has already been deleted.

## Completion Conditions and Exclusions

Completion is confirmed by completed scenarios and actual application check commands. Album window, quotas, parser isolation, and cancellation are defined in OPERATIONS/USER_FLOWS. A resource error is not reported as a missing field.

Recognition, a new UI outside Telegram, document archive, OCR stage, persistent queue, bypassing 20 MB, or introducing a new user limit without agreement are out of scope.
